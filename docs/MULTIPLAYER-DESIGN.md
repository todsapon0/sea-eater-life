# เล่นพร้อมกันครอบครัว (v1.0) — เอกสารออกแบบ ร่าง v0

สถานะ: ร่างให้ผู้ใช้ตรวจ · **ยังไม่เขียนโค้ด** · ต้องรอระบบบัญชี (Supabase) ตั้งค่าก่อน

## 1. เป้าหมายและข้อจำกัด
- เด็กกับครอบครัว (2–4 คน) เล่นแมพเดียวกันพร้อมกันบน iPad/iPhone
- **ความปลอดภัยเด็ก:** ห้องส่วนตัวด้วยรหัสเชิญเท่านั้น ไม่มีห้องสาธารณะ ไม่มีแชทพิมพ์อิสระ (ใช้อีโมจิ/วลีสำเร็จรูปเท่านั้น) ไม่เก็บข้อมูลส่วนตัว ไม่ค้นหาผู้เล่นแปลกหน้า
- **งบ:** บริการฟรีเท่านั้น ห้ามผูกบัตร/จ่ายเงินโดยไม่ได้รับอนุมัติ
- ต้องไม่กระทบโหมดเล่นคนเดียวและเซฟเดิม

## 2. ขอบเขต v1.0 (เล็กที่สุดที่เล่นสนุกได้)
- ห้อง 1 ห้อง = 1 แมพ, สูงสุด 4 คน, สร้างห้องได้ได้รหัส 4–6 ตัว
- เห็นผู้เล่นอื่น (ตำแหน่ง ท่า คลาส ชื่อเล่นที่เลือกจากรายการ) + เห็นเอฟเฟกต์โจมตี
- มอนสเตอร์: ให้เจ้าของห้อง (host) คำนวณ แล้วส่งสถานะให้คนอื่น
- ดรอป/EXP: แยกรายคน ไม่แย่งกัน; ไม่มีการค้าขายไอเทมใน v1.0
- ไม่ทำ: PvP, แชทอิสระ, ห้องสาธารณะ, ตารางอันดับ

## 3. ทางเลือกเทคนิค (ฟรี)
| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| A. Supabase Realtime (broadcast/presence) | ใช้บัญชีที่วางไว้แล้ว ฟรีเทียร์ ไม่ต้องมีเซิร์ฟเวอร์เอง | โควตาฟรีจำกัด (ข้อความ/วินาที, การเชื่อมต่อพร้อมกัน) ต้องเช็กตัวเลขล่าสุดก่อน |
| B. WebRTC peer-to-peer (signaling ผ่าน Supabase) | ลดโหลดเซิร์ฟเวอร์ ความหน่วงต่ำ | ผ่าน NAT/Wi-Fi บ้านบางทีไม่ติดต้องมี TURN (ไม่ฟรี) ยากกว่า |
| C. เซิร์ฟเวอร์เกมเอง (Cloudflare Workers/Durable Objects ฯลฯ) | ควบคุมได้เต็มที่ | ต้องดูแล โค้ดมาก อาจมีค่าใช้จ่าย |
- **เสนอ: A** (host-authoritative) เริ่มเล็ก ถ้าโควตาไม่พอค่อยพิจารณา B
- ตรวจโควตาและเงื่อนไขล่าสุดของ Supabase ก่อนลงมือ (ตัวเลขเปลี่ยนได้)

## 4. สถาปัตยกรรมโดยย่อ
- ช่อง realtime ต่อห้อง `room:<รหัส>`; presence = รายชื่อผู้เล่น
- ผู้เล่นส่งสถานะตัวเอง ~10 ครั้ง/วินาที (x,z,ทิศ,ท่า,HP) แล้วเกมฝั่งรับ interpolate
- host ส่งสถานะมอนสเตอร์ ~5–10 ครั้ง/วินาที เฉพาะตัวใกล้ผู้เล่น (ข้อมูลน้อย)
- ผู้เล่นอื่น = โมเดลคลาสเดียวกับของตัวเอง (ใช้ตัวโหลดฮีโร่ที่ทำไว้ Task A) + ป้ายชื่อ
- ถ้า host หลุด: ย้าย host อัตโนมัติ หรือปิดห้องพร้อมข้อความ (v1.0 เลือกอย่างง่าย: ปิดห้อง)
- เซฟ: ทุกคนเซฟของตัวเองในเครื่อง/บัญชีตัวเอง เหมือนเดิม; ห้องไม่แก้เซฟคนอื่น

## 5. ความเสี่ยง
1. **ประสิทธิภาพ iPad 8:** FPS เฉลี่ย 33–38 อยู่แล้ว → จำกัดผู้เล่น 4 คน, โมเดลคนอื่น LOD ต่ำ, วัดด้วย test-performance
2. **โควตาฟรีหมด/บริการเปลี่ยนเงื่อนไข** → แสดงข้อความไทยเข้าใจง่าย และเล่นคนเดียวต่อได้เสมอ
3. **ความปลอดภัยเด็ก** → รหัสห้องสั้นอายุจำกัด ไม่แสดงข้อมูลบัญชี/อีเมล ตัวเลือกชื่อเล่นจากรายการ
4. **โกง/ข้อมูลปลอม** → ระดับครอบครัวยอมรับได้; จำกัดค่า sanity (ตำแหน่ง ความเร็ว) ฝั่งรับ
5. **ความซับซ้อน/บั๊ก** → เทสต์อัตโนมัติจำลอง 2 ผู้เล่น (2 หน้าเบราว์เซอร์) ก่อนให้เด็กลอง

## 6. ลำดับทำงานเสนอ
1. ผู้ใช้ตั้ง Supabase (ค้างอยู่ใน QUESTIONS.md) → เปิดบัญชีจริง
2. Spike: ห้อง + presence + ส่งตำแหน่ง 2 คน (กิ่งทดลอง) วัดความหน่วง/โควตา
3. แสดงผู้เล่นอื่น + ป้ายชื่อ + อีโมจิ
4. มอนสเตอร์แบบ host-authoritative + ดาเมจ/ดรอปรายคน
5. เทสต์ 2–4 ผู้เล่น + วัดประสิทธิภาพ → ให้ครอบครัวลองบน iPad → ปล่อยเป็น v1.0 (ต้องผู้ใช้สั่งรวม main)
