# คิวงาน Claude ⇄ โค (Codex) — วนงานอัตโนมัติผ่านไฟล์นี้

**กติกา (ทั้งสองฝ่ายอ่านก่อนทำ):**
- ไฟล์นี้คือคิวงานเดียว ลำดับบนก่อน สถานะ: `TODO` (ยังไม่เริ่ม) → `DOING` (มีคนกำลังทำ ใส่ชื่อ+เวลา UTC) → `REVIEW` (ฝั่งทำเสร็จ ส่งต่อให้อีกฝ่ายตรวจ/ต่อ) → `DONE` | `BLOCKED(เหตุผล)` | `รอผู้ใช้` (ต้องผู้ใช้อนุมัติ/ทดสอบ ห้ามข้าม)
- **โค (Codex):** เลือกงานแรกที่ owner=CODEX และ `TODO` ที่ไม่ติด `รอผู้ใช้` อยู่ก่อนหน้า → แก้เป็น `DOING` + commit/push ทันที (กันชน) → ทำตามรายละเอียดงานใน `CODEX-PROMPT.md` (แตะเฉพาะ `assets/` + `docs/`; ห้ามแก้ `index.html`; ห้ามรัน `review.sh`; ประหยัดโควตา) → push ไฟล์ → เปลี่ยนเป็น `REVIEW` + เขียนผลสั้นๆ (ไฟล์/ขนาด/triangles) ใต้งานนั้น → ทำงาน CODEX ถัดไปต่อเลยถ้ามี ถ้าไม่มีให้หยุด
- **Claude:** ตรวจคิวทุกรอบที่ตื่น → งาน `REVIEW` ของโค: ผูกเข้าเกม ทดสอบ วัดภาระ → `DONE` + **รายงานผู้ใช้ทุกครั้งที่จบ 1 งาน** → ถ้างานถัดไปเป็น `รอผู้ใช้` ให้หยุดรอ

- **หยุดชั่วคราว:** ถ้าบรรทัดนี้เป็น `PAUSED: yes` ทุกฝ่ายต้องหยุด — `PAUSED: no`

## การอนุมัติจากผู้ใช้ (2026-11-02 16:48)
ผู้ใช้อนุมัติให้ทั้งสองฝ่ายทำตามคิวนี้/โรดแมพต่อเนื่องไปเอง **ยกเว้นเรื่องสำคัญที่ต้องรอผู้ใช้** ผู้ใช้จะเข้ามาถามเองว่าติดอะไรหรือต้องตัดสินใจอะไร — ดังนั้น:
- **ทำต่อเนื่องบนสาขา `claude/family-build` เท่านั้น** ห้าม merge เข้า `main` ห้าม deploy Production จนกว่าผู้ใช้สั่งตรงๆ (ครั้งที่เด็กเห็นโมเดล Sea Eater เปลี่ยนแล้วร้องไห้ คือบทเรียน)
- **ต้องรอผู้ใช้เสมอ:** หน้าตาตัวละครที่เด็กรู้จัก (Sea Eater/Bloop/Maja ใหม่) · การรวมเข้า main · เรื่องเงิน/บัญชีบริการภายนอก/ข้อมูลส่วนตัว · เปลี่ยนสมดุลเกมหรือเซฟแบบกระทบผู้เล่น · งานที่ใช้เกินโควตาที่ตกลง
- **ไม่ต้องรอ (ทำเลย):** มอนสเตอร์ตามสไตล์/คอนเซปต์ที่อนุมัติแล้ว, ตัวโหลด/เทสต์/เอกสาร/แก้บั๊ก, ปรับประสิทธิภาพ
- เรื่องที่ต้องให้ผู้ใช้ตัดสินใจ ให้เขียนสั้นๆ ลง `docs/QUESTIONS.md` (ข้อละ 1–2 บรรทัด พร้อมตัวเลือกที่แนะนำ) แล้วทำงานอื่นต่อ ห้ามหยุดทั้งคิวเพราะเรื่องเดียว; ผู้ใช้อ่านเองเมื่อว่าง
- **รายงานผู้ใช้:** Claude รายงานสั้นๆ เมื่อจบงานสำคัญ/มีเรื่องต้องตัดสินใจ/ติดปัญหา (ไม่ต้องรายงานรอบที่ไม่มีอะไรใหม่)
